# 权限引导

OpenFlow 的核心交互依赖三类权限，缺一不可。每个权限只用于其字面用途，**不收集任何额外信息**。本页解释每个权限的用途、申请方式与撤回方式。

## 1. 无障碍服务（Accessibility Service）

**为什么需要**：
- 感知当前哪个输入框处于焦点状态（决定是否显示悬浮球）
- 在识别完成后，通过 `AccessibilityNodeInfo.ACTION_SET_TEXT` 把文本写入光标位置

**开启路径**：
```
设置 → 辅助功能 → 已下载的服务 → OpenFlow → 开启
```
（不同厂商 ROM 路径略有差异：可能在「辅助功能 / 无障碍 / 已安装的服务」下。）

**风险与边界**：
- OpenFlow 只在悬浮球被长按时主动写入文本；不在后台读取屏幕内容。
- 源码中所有无障碍相关代码集中在 `app/src/main/java/com/hank/flow/open/service/FlowAccessibilityService.kt`，可自行审查。

## 2. 悬浮窗（Display over other apps / SYSTEM_ALERT_WINDOW）

**为什么需要**：让悬浮球能浮在其它 App 之上。

**开启路径**：
```
设置 → 应用 → OpenFlow → 显示在其它应用上层 → 允许
```
或在 App 内点击「去授权」由系统跳转。

**说明**：Android 12 及更高版本对该权限有较严格的提示与显示规范。OpenFlow 的悬浮球面积小、可移动、可在设置中临时隐藏。

## 3. 麦克风 + 麦克风类型前台服务

**为什么需要**：
- `RECORD_AUDIO` —— 实际录音
- `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MICROPHONE`（Android 14+ 要求）—— 让录音在前台服务中合法进行，并在通知栏显示「正在录音」提示

**开启路径**：
首次长按悬浮球录音时，系统会弹窗请求麦克风权限。选「使用应用时允许」即可。
若被拒绝，可在「设置 → 应用 → OpenFlow → 权限 → 麦克风」重新开启。

**通知栏的录音提示**：是系统对前台麦克风服务的强制要求，**不可在 App 内关闭**，这正是设计为可见的——任何在录音的 App 都必须告知用户。

## 撤回所有权限

如希望停止使用 OpenFlow 而暂不卸载：

1. 在「设置 → 辅助功能」中关闭 OpenFlow 的无障碍服务
2. 在「设置 → 应用 → OpenFlow → 权限」中关闭悬浮窗与麦克风
3. 悬浮球将不再出现，App 也不会再启动任何后台服务

或者直接卸载（会同时清除模型与设置）。

## 常见拦截

| 现象 | 通常原因 |
|---|---|
| 悬浮球完全不出现 | 无障碍服务未开 / 悬浮窗权限未授予 |
| 长按悬浮球无反应 | 麦克风权限未授予 / 前台服务未启动（重启 App 试试） |
| 写入文本失败 | 当前输入框是 WebView 或非标准控件（少数 App 会拦截 `ACTION_SET_TEXT`） |
| 部分厂商 ROM 杀后台 | 把 OpenFlow 加入「电池白名单 / 后台保活」白名单 |
